## بخش A — خلاصه برای مالک (فارسی ساده)

### ابزار چیست
یک وب‌اپ فارسی (راست‌به‌چپ) به‌علاوه یک MCP سرور. آدرس یک پیج اینستاگرام را می‌دهی؛ ابزار پیج را تحلیل می‌کند، رقبا را پیدا و تحلیل می‌کند، برای هر هفته استراتژی می‌سازد، پست/استوری/ریلز تولید می‌کند، آن‌ها را در قالب اینستاگرام نشان می‌دهد و روی تقویم هفتگی می‌چیند، و برای هر قطعه پرامپت متنی برای AI های دیگر می‌دهد.

### کاربر
V1: فقط مالک (و شاید تیم داخلی) با یک لاگین ساده. مشتریان با لاگین جدا (ب) و سرویس عمومی (ج) بعداً، و معماری از اول برای آن آماده می‌شود.

### جریان کار
آدرس پیج ← دریافت داده (Apify یا دستی) ← پیشنهاد رقبا (Bio + هشتگ + دستی) ← تأیید مالک ← تحلیل الگوی رقبا (بدون کپی) ← استراتژی هفته N ← تولید محتوا + بازبینی کیفیت و اصالت ← پیش‌نمایش اینستاگرام + تقویم drag & drop ← پرامپت برای AI های دیگر ← ورود نتایج عملکرد ← استراتژی هفته N+1.

### جدایی داده مشتریان
- هر پروژه (آرازسیستم هم) یک workspace مستقل است و در کد هیچ استثنایی ندارد.
- هر پروژه پایگاه‌داده SQLite جدا و پوشه دارایی جدا دارد و به‌صورت یک فایل bundle قابل export/import است.

### پروفایل برند هر مشتری
ورودی: لوگو، فونت، پالت رنگ، برندبوک PDF، نمونه تصاویر. ابزار آن‌ها را به پروفایل ساختاریافته (رنگ، تایپوگرافی، چیدمان، لحن، کارها و نکردنی‌ها، سبک تصویر) تبدیل می‌کند و قبل از ذخیره پیش‌نمایش و تأیید انسانی می‌خواهد. پروفایل آرازسیستم «موقت» علامت می‌خورد چون هویت بصری در حال بازطراحی است.

## بخش B — مرحله ۱: جداسازی (الزامی، قبل از هر کد)

هدف: ابزار با ریپوی داخلی آرازسیستم قاطی نشود.

1. ساخت ریپوی جدید (مالک حساب را می‌دهد؛ دسترسی این جلسه به ریپوی جدید باید جداگانه اضافه شود).
2. مرور و برداشتن **فقط لازم‌ها** از این ریپو، به‌صورت نسخه عمومی‌شده در `prompts/` ریپوی جدید.
   نامزدها (هر کدام هنگام انتقال خوانده و بازبینی می‌شود):
   - پرامپت‌های `.claude/agents/`: `research-intelligence`، `growth-strategist`، `content-planner`، `content-writer`، `story-producer`، `quality-editor`، `prompt-engineer`
   - قواعد کیفیت، اصالت، تأیید و داده‌محوری از `CLAUDE.md` (بندهای ۳، ۴، ۵، ۶)
   - ساختار قالب‌ها از `templates/` و قواعد تایپوگرافی/اوورلی از `templates/production/`
   - ساختار خروجی از `delivery/`
3. **برداشته نمی‌شود:** هر چه اختصاصی آرازسیستم است — `brand/`، `knowledge/`، `strategy/`، `portfolio/`، `competitors/`، `analytics/`، `calendar/`، `articles/`، `content/` و داده مشتریان. این‌ها در ابزار به‌صورت «پروفایل پروژه» داخل دیتابیس هر پروژه می‌آیند، نه فایل ثابت.
4. خروجی مرحله: فهرست دقیق فایل‌های برداشته‌شده و حذف‌شده، برای تأیید مالک.
5. کپی دستی و نسخه‌دار؛ بدون submodule و بدون وابستگی پنهان.

## بخش C — ضمیمه فنی (برای اجرا؛ مالک لازم نیست بخواند)

### معماری
- یک Cloudflare Worker (Hono) برای REST، MCP و فایل‌های ثابت UI. جهت‌گیری: منطق هسته TypeScript خالص؛ وابستگی پلتفرم پشت portها (`Storage`، `BlobStore`، `JobQueue`، `DataProvider`، `LLM`، `Renderer`) با adapter کلادفلر (Durable Objects SQLite، R2، Queues، Browser Rendering) و adapter هاست (فایل SQLite، fs/S3، صف درون‌فرایندی، Playwright). جزئیات و محدودیت‌های هر سرویس کلادفلر هنگام پیاده‌سازی از مستندات رسمی تأیید می‌شود.
- دو سطح داده: صفحه کنترل کوچک (کاربر، فهرست پروژه، اشاره‌گر) و صفحه داده جدا برای هر پروژه. سرویس‌ها فقط `projectId` می‌گیرند.
- ترتیب ساخت: سرویس‌های هسته ← REST/UI ← MCP (لایه نازک روی همان سرویس‌ها).

### قراردادها
1. کارهای سنگین job غیرهمزمان‌اند (`jobId` + `job_status`).
2. خروجی هر فراخوانی Claude با schema اعتبارسنجی می‌شود؛ یک retry با پیام خطا؛ سپس شکست شفاف؛ هرگز ذخیره داده نامعتبر.
3. پرامپت‌ها فایل‌های نسخه‌دار؛ هر خروجی نسخه پرامپت و مدل را ثبت می‌کند.
4. `cost_estimate` قبل از هر job، سقف هزینه، و ثبت هزینه واقعی (Apify + توکن).
5. امنیت V1: نشست امن تک‌کاربره، توکن جدا برای MCP، کلیدها فقط سمت سرور.
6. هیچ port یا tool برای انتشار در اینستاگرام وجود ندارد.
