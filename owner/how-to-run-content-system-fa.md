# راهنمای عملیاتی — چطور با این سیستم کار کنید

این راهنما کاملاً عملی است: دقیقاً چه چیزی بگویید تا سیستم کار درست را
انجام بدهد، بدون اینکه لازم باشد ساختار داخلی مخزن یا اسم ایجنت‌ها را
بدانید.

**نقش شما در این سیستم:** مدیر خلاقیت و تصمیم‌گیرنده نهایی هستید — نه
اپراتور روزانه Canva، نه نویسنده پرامپت، نه هماهنگ‌کننده دستی تولید، و
نه جمع‌آوری‌کننده اسکرین‌شات (مگر وقتی تحصیل خودکار دارایی شکست بخورد).
هدف سیستم این است که با گذشت زمان، کار شما کمتر شود.

---

## الف) بازبینی استراتژی ماهانه

**دستور نمونه:**
```
استراتژی ماهانه اینستاگرام بعدی رو بر اساس این‌ها آماده کن:
- استراتژی برند تأییدشده
- عملکرد ماه قبل
- اولویت‌های کسب‌وکار
```

**سیستم نشان می‌دهد:**
- چه چیزی باید بماند
- چه چیزی باید تغییر کند
- اولویت‌های ماه بعد

**قانون مهم:** بدون تأیید صریح شما، هیچ فایل منبع اصلی (source of truth)
تغییر نمی‌کند.

---

## ب) تقویم ماهانه

**دستور نمونه:**
```
تقویم ۳۰ روزه محتوای اینستاگرام بعدی رو بر اساس استراتژی تأییدشده بساز.
```

برای هر آیتم این فیلدها می‌آید:
- روز
- فرمت
- موضوع
- هدف
- هوک
- CTA
- دارایی موردنیاز

---

## پ) تولید هفتگی

**دستور نمونه:**
```
بسته‌های محتوای تأییدشده هفته بعد رو از روی تقویم ماهانه آماده کن.
```

سیستم این‌ها را می‌سازد:
- کپی
- اسکریپت
- استوری‌بورد
- جهت‌گیری خلاقانه (design direction)
- نیازمندی‌های دارایی (asset requirements)
- پرامپت‌های تولید

**قانون مهم:** استراتژی یا تقویم در این مرحله تغییر نمی‌کند.

---

## ت) محتوای تکی نمونه‌کار (پروژه/وب‌سایت)

کمترین ورودی موردنیاز از شما:
```
نام سایت:
URL:
نوع محتوا:
هدف اختیاری:
```

از همین‌جا، سیستم به‌طور خودکار این مسیر را طی می‌کند:

```
تحصیل دارایی (اسکرین‌شات واقعی)
→ تحلیل نمونه‌کار
→ زاویه محتوا
→ کپی
→ جهت‌گیری خلاقانه
→ انتخاب قالب
→ مهندسی پرامپت
→ مسیریابی تولید
→ تولید
→ بازبینی کیفیت
→ بازبینی مالک
```

شما معمولاً نباید خودتان پرامپت تصویر یا ویدیو بنویسید — این کار سیستم
است.

**اگر تحصیل خودکار دارایی شکست بخورد** (مثلاً دسترسی شبکه به سایت مسدود
باشد)، سیستم دقیقاً می‌گوید چه فایلی لازم دارد (`OWNER ASSET REQUIRED`).
مطمئن‌ترین راه رساندن آن فایل، کامیت مستقیم در گیت‌هاب مخزن است — پیست یا
ضمیمه‌کردن تصویر داخل همین چت، فایل واقعی را به سیستم نمی‌رساند (این یک
محدودیت شناخته‌شده محیط اجراست، نه چیزی که با تلاش بیشتر در چت حل شود).

---

## ث) دستورهای تأیید مالک

- **«تأیید شد»** → نهایی‌سازی و آماده انتشار
- **«نیاز به اصلاح دارد — [بازخورد دقیق]»** → یک دور اصلاح عادی (طبق
  `templates/production/revision-policy.md`، معمولاً فقط یک دور)
- **«رد شد»** → پیشنهاد یک جهت‌گیری خلاقانه جدید (نه فقط اصلاح جزئی)

نکته: بازخوردهای جزئی و سلیقه‌ای (POLISH) — مثل یک اختلاف کوچک در
فاصله‌گذاری — باعث چرخه بی‌پایان اصلاح نمی‌شوند. فقط مشکلات واقعی
(BLOCKER: اطلاعات غلط، دارایی/رابط‌کاربری جعلی، متن ناخوانا، مشکل
راست‌به‌چپ، ابعاد غلط، نقض قوانین برند) یک دور اصلاح اضافه را توجیه
می‌کنند.

---

## ج) هماهنگ‌سازی استراتژی

اگر تغییری را در نسخه فارسیِ پوشه `owner/` تأیید کنید (مثلاً اصلاح یک
متن یا تصمیم)، این تغییر باید در فایل فنی منبع اصلی هم اعمال شود — نه
فقط در نسخه فارسی. پوشه `owner/` فقط محل مرور و تصمیم‌گیری است، نه محل
ثبت نهایی تصمیمات فنی (طبق `owner/README.md`). وقتی تأییدی می‌دهید، همان
لحظه هر دو نسخه (فارسیِ owner و فایل فنی منبع) به‌روزرسانی می‌شود.

---

## چند نکته کلی

- انتشار همیشه به هر دو نیاز دارد: **تأیید کیفیت** + **تأیید صریح و فعلی
  شما**. هرگز به‌صورت خودکار منتشر نمی‌شود.
- اگر تصویری واقعی سایت باید حفظ شود (نمونه‌کار)، سیستم هرگز رابط‌کاربری
  را با هوش مصنوعی بازسازی نمی‌کند — یا از فایل واقعی استفاده می‌شود، یا
  از شما دارایی واقعی درخواست می‌شود.
- فونت و سبک بصری فعلی (Vazirmatn) یک استاندارد تولید موقت است، نه هویت
  نهایی برند — وقتی هویت بصری نهایی تأیید شد، جایگزین می‌شود.
